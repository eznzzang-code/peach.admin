# 설문 관리 개발팀 전달 자료

기준: 관리자 프런트엔드 STEP 3~13-2. 서버 API, DB, 회원 응답 화면은 이 저장소에 없습니다. 없는 필드를 운영 스키마로 확정하지 않습니다.

구분: **구현 완료**는 화면에서 동작하는 프런트엔드, **서버 연동 필요**는 안내만 있고 저장·조회가 없는 기능, **개발 협의 필요**는 스키마와 정책이 확정되지 않은 항목, **테스트 전용**은 Mock Data와 응답 결과 미리보기입니다. 응답자 자격, 중복 제출 방지, 제출 마감 강제는 구현 완료가 아닙니다.

## A. 현재 구현 상태

### 프런트엔드에서 동작

- 등록 설문 목록 정렬, 상태 탭, 상태 드롭다운 동기화, 제목·소개 검색, 기간 필터, 10건 페이지
- 설문 상태 계산, 진행예정 응답수 `-`, 응답보기 진입 제한
- 신규등록·진행예정 수정의 입력 검증. 문항 편집과 제출이 `surveyQuestionIssue`를 함께 사용
- 종료일 없음, 이탈 확인
- 목록 상태는 탭·검색·초기화 때 현재 시각으로 다시 계산. 화면을 열어 둔 자동 갱신은 없음
- 수정 완료와 수동 종료 확인은 실행 시점 상태를 다시 계산. 종료로 바뀌면 저장 안내로 진행하지 않음
- 문항 추가·복제·삭제·순서 변경·유형 변경·적용 전 부모 데이터 유지
- 대상 선택 UI와 OR·AND 안내 문구, 적용 전 부모 데이터 유지
- 읽기 전용 미리보기
- 임시저장 목록 정렬, 빈 제목, 작성 상태 자동 계산, 10건 페이지
- 상세 표시, 상태별 수정·종료 버튼, 응답 0건 삭제 버튼
- 수정 시 원본 깊은 복사, 진행중 필드 잠금, 종료 설문 차단
- 삭제·수동 종료의 확인 모달, 실행 직전 재검증, 확인 버튼 중복 실행 방지
- 응답 결과 접근 제한, 객관식 통계 규칙, 주관식 10건 페이지와 줄바꿈
- 1280px 기준 레이아웃. 세로 스크롤바가 있을 때 본문 최소 너비는 창 너비

### Mock Data에 의존

- `MockData.surveys`: 등록 설문. 화면 검수용 25건. 운영 데이터가 아님
- `MockData.surveyDrafts`: 임시저장. 화면 검수용 1건(id `D1`, 제목 없음)
- 지역·회원 구분 선택지는 `surveys.js`의 `SURVEY_TARGET_OPTIONS`와 `surveyAudienceOptions`. 코드 주석상 확정 업무 데이터가 아님
- 설문 객체에 `questionResults`가 없어 결과 화면은 미연결 안내가 기본

### 테스트 데이터 미리보기 전용

- 파일: `js/survey-results-demo.js`
- 기본 꺼짐. `String(survey.id) === "25"`만 지원
- 화면 메모리에만 30건 분량의 통계·주관식을 만듦
- 상단 전체 유효 응답 수는 기존 `responseCount` 유지
- 문항 라벨만 “테스트 유효 응답 수”
- 배너: “테스트 데이터입니다. 실제 설문 응답이 아닙니다.”
- 운영 배포 전 제거 시점은 **개발 협의 필요**

## C. 데이터 구조

아래는 코드에 있는 필드입니다. 서버 전용 필드는 적지 않았습니다.

### 등록 설문 `MockData.surveys[]`

| 필드 | 코드에서의 의미 |
| --- | --- |
| `id` | 숫자. 주소 비교는 문자열로 함 |
| `title` | 설문명 |
| `intro` | 소개. 목록 “내용” 검색 대상 |
| `startAt` | `YYYY.MM.DD HH:MM` |
| `endAt` | 같은 형식. `noEnd`이면 빈 문자열 |
| `noEnd` | 종료일 없음 |
| `manualClosed` | true면 기간과 관계없이 종료 |
| `responseCount` | 설문 단위 응답 수. 문항별 수치가 아님 |
| `target` | 작성 화면 초안의 구조화된 대상. `mode`, `regions`, `memberTypes`. 현재 등록 Mock에는 없음. 서버 저장 시 원본으로 권장 |
| `targetLabel` | 화면 표시용 파생 문자열. 현재 Mock은 `"전체 회원"`. 조건이 바뀌면 이 문자열을 다시 만드는 방향 |
| `registeredAt` | 목록 정렬용 `YYYY.MM.DD HH:MM` |
| `questions` | 문항 배열 |
| `questionResults` | 결과 화면이 읽음. 현재 Mock에는 없음 |

### 문항

| 필드 | 코드에서의 의미 |
| --- | --- |
| `type` | Mock·상세는 `단일 선택`, `복수 선택`, `주관식`. 편집 초안은 `single`, `multi`, `text` |
| `title` | 문항 제목 |
| `description` | 설명. Mock은 빈 문자열 |
| `required` | 필수응답. 값이 아니면 필수로 처리 |
| `choices` | `{ text }` 배열. 주관식은 빈 배열 |
| `id`, `order` | 편집 중인 화면 초안에만 있음. Mock 문항에는 없음 |

### 대상 데이터

이번 단계에서 Mock Data는 바꾸지 않았습니다.

| 구분 | 역할 | 현재 코드 |
| --- | --- | --- |
| `target` | 구조화된 원본. `mode`는 `unset`, `all`, `conditions`. 지역·회원 구분은 id 배열 | 등록·수정 화면 메모리. Mock 등록 설문에는 없음 |
| `targetLabel` | 화면 표시용 파생 문자열 | Mock 등록 설문은 `"전체 회원"`. 임시저장 D1은 빈 문자열 |

서버 연동 시 `target`을 저장하고, 목록·상세의 문구는 그 조건으로 `targetLabel`을 생성하는 방향을 권장합니다. 최종 API 필드명과 코드값은 **개발 협의 필요**입니다.

### 작성 화면 대상 초안

Mock 설문에는 이 객체가 없고, 등록·수정 화면 메모리에만 있습니다.

| 필드 | 값 |
| --- | --- |
| `mode` | `unset`, `all`, `conditions` |
| `regions` | 옵션 id 배열 |
| `memberTypes` | 옵션 id 배열 |

화면 검수용 id: 지역 `gyeonggi`, `gangwon`, `chungbuk`, `chungnam`, `jeonbuk`, `jeonnam`, `gyeongbuk`, `gyeongnam`. 회원 `farm`, `company`, `distribution`, `other`. 운영 코드 **개발 협의 필요**.

### 임시저장 `MockData.surveyDrafts[]`

`id`(예: `D1`), `title`, `intro`, `startAt`, `endAt`, `noEnd`, `manualClosed`, `responseCount`, `targetLabel`, `registeredAt`, `updatedAt`, `questions`.

`updatedAt`이 목록 정렬 기준입니다. 이어 작성은 이 객체를 폼에 넣지 않습니다.

### 결과 레코드

코드가 기대하는 형태입니다. Mock에는 샘플이 없습니다.

객관식:

- `respondentCount`: 0 이상 정수
- `choices`: 선택 수 배열, 또는 `{ count }` 객체 배열. 길이는 선택지 수와 같음

주관식:

- `respondentCount`: 0 이상 정수. 없으면 표시 `—`
- `answers[]`: `text`, `submittedAt`(`YYYY.MM.DD HH:MM`). 다른 속성은 표시에 쓰지 않음

응답자 식별자, 회원 id, 중복 키, 개인정보 필드는 코드에 없습니다. **개발 협의 필요**.

### 테스트 미리보기 반환값

`SurveyResultsDemo.build()`가 문항 순서대로 위와 같은 객체를 메모리에만 만듭니다. `respondentCount`는 30입니다. 설문 필드에 대입하지 않습니다.

## D. 서버 검증

클라이언트 검사만으로 끝나면 안 되는 항목입니다.

| 동작 | 서버가 다시 볼 내용 |
| --- | --- |
| 등록 | 필수값, 시작일시 ≥ 기준 시각, 종료일시 > 기준 시각, 종료일시 > 시작일시, 종료일 없음, 대상, 문항 1개 이상, 문항 제목, 객관식 2~10개와 문구, 지원하지 않는 유형 거부. 클라이언트도 제출 직전에 같은 문항 검사를 함 |
| 수정 | 실행 시점 상태. 종료는 거부하고 저장 안내로 넘어가지 않음. 진행중은 시작일시·대상·문항 변경 거부. 종료일시가 기준 시각과 시작일시보다 늦은지 |
| 삭제 | 실행 시점 응답 수가 0인지. 목록의 여러 id를 각각 확인 |
| 수동 종료 | 실행 시점 상태가 진행중인지. 이미 종료면 거부. 종료 후 수정·재개 거부 |
| 임시저장 삭제·복원 | 초안 존재, 요청자 권한 |
| 응답 제출 | 진행중인지, 대상 조건에 맞는지, 중복인지, 필수 문항인지, 주관식 길이. 관리자 화면에는 이 검증이 없음 |
| 통계·Excel·기간 조회 | 조회 권한. 비율은 서버 집계를 신뢰. 단일 선택 합과 응답 수 불일치는 오류로 다루는 현재 화면 규칙과 맞출지 **개발 협의 필요** |

상태 경계: 시작 시각 포함은 진행중, 종료 시각 포함은 종료, 종료일 없음은 수동 종료 전까지 진행중.

## E. 개발 협의 필요사항

1. 지역·회원 구분의 실제 코드와 이름. 현재 8개·4개는 화면 검수용입니다.
2. 서버 저장 구조. 권장안은 구조화된 `target` 저장과 `targetLabel` 파생입니다. 최종 스키마와 문항 `type`의 한글·영문 표기는 **개발 협의 필요**.
3. 응답자 식별과 중복 방지. 회원당 1회인지, 비로그인 허용인지 코드에 없음.
4. 관리자 권한. 설문 메뉴는 권한 분기 없이 링크로만 연결되어 있음. 등록·수정·삭제·종료·결과·Excel 권한 분리 여부.
5. 상태·검증의 기준 시각과 시간대. 현재는 브라우저 로컬 시각이며, 목록은 탭·검색·초기화 때 다시 계산합니다. 열어 둔 화면의 자동 갱신은 없습니다.
6. 응답 조회 권한과 개인정보. 주관식 원문을 관리자 화면과 Excel 중 어디에 둘지. Excel 주석은 원문과 개인정보 제외.
7. Excel을 서버에서 만들지, 집계 JSON을 받아 프런트에서 만들지.
8. 테스트 데이터 미리보기를 검수 빌드에만 둘지, 연동 후 화면에서 제거할지.

## F. 연동 시 유지할 화면 계약

- 저장·삭제·종료 실패와 미구현을 성공처럼 보이지 말 것
