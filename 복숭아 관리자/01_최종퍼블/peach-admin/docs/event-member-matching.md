# 행사·교육 회원 확인 연결

participant.html의 회원 확인 후 계속 → 이름/휴대폰 번호 팝업 → 기존 복숭아자조금 회원 매칭 → 신청 문항으로 바로 이동합니다. 내 참여내역 요청 중 확인하면 본인 내역으로 돌아갑니다. 회원가입이나 SMS 단계를 추가하지 않습니다. 행사 신청 결과는 기존과 같이 유지하고 인증 시도/결과의 별도 저장 화면·이력은 만들지 않습니다.

js/participation/member-auth.js는 인증된 회원 식별을 현재 페이지 메모리에서만 보관합니다. localStorage/sessionStorage에 이름·번호·확인 결과를 쓰지 않습니다. 새로고침하면 회원 확인이 다시 필요합니다. 이름·휴대폰 입력은 요청 시에만 사용합니다. 기존 임의 테스트 회원 자동 통과는 제거했습니다.

PeachEventMemberApi.matchMember({name,phone})를 실제 회원 조회 API에 연결합니다. phone은 숫자만 전달합니다. 성공 응답은 {verified:true,member:{id:"회원의 고유 식별값",name:"등록 이름"},verificationToken:"필요 시 단기 증빙"}입니다. 불일치/조회 실패/잘못된 식별값은 진행하지 않습니다. verificationToken을 사용하면 현재 요청 흐름에서만 전달하고 응답 데이터·영구 저장소에 보관하지 않습니다. 취소 뒤 도착한 응답은 적용하지 않습니다.

실제 회원 서버는 회원 데이터의 이름·전화 매칭을 수행합니다. 별도 계정을 만들거나 인증 결과를 응답 결과에 추가하지 않습니다. 신청 및 본인 내역 조회는 확인한 회원에게 귀속하고, 프런트가 넘긴 임의 회원 ID만으로 권한을 인정하지 않습니다. 기존 신청 응답에는 기존 정책대로 memberId/name을 유지합니다. 현재 기본 어댑터는 실제 회원 정보를 가지고 있지 않으므로 연결 전에는 실패 안내만 표시하며, 임의 회원으로 성공 처리하지 않습니다.


## 실패·이탈 처리
- 불일치와 조회 실패는 팝업을 닫지 않고 이름·휴대폰 입력을 유지합니다. 같은 팝업에서 수정·재시도합니다.
- 확인 요청 중 취소한 응답은 무시하며, 취소 후 다시 연 요청에 영향을 주지 않습니다.
- 질문 화면 직접 진입에도 회원 확인·기간·공개·정원·중복 상태를 검사합니다.
- 회원 확인 결과는 현재 페이지 메모리에서만 사용합니다. 새로고침 후 다시 확인합니다.
